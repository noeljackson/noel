## Summary

- v2 is a new protocol, not a revision of protocol 4. Nothing on the wire is
  shared except the Delta op encoding inside parts. noel-chord's `wire.rs`,
  `link.rs` and most of `host.rs` get rewritten; `delta/` and the canonical
  JSON helpers stay.
- The v2 wire is **not stable**. `PROTOCOL_VERSION` is still 1 even though
  slices 3b and 4a changed messages, "nothing is deployed" (`docs/slices.md:179-182`,
  `docs/design.md:2066-2068`). Slice 9 (telemetry) is still to come and will
  add trace carriers to `hold` and `call` (`docs/design.md:2155-2156`,
  `docs/slices.md:76`).
- There are no recorded frames or conformance suite upstream. Goldens have to
  be generated by noel's own fixture scripts, as `chord-link.json` is today.
- Upstream v1 now exists only as the npm release `@earendil-works/chord@1.5.0`
  (`CHANGELOG.md:8`). noel's protocol 4 should still talk to 1.5.0's v1
  **(unverified;** see "Open questions").

## 1. Link and wire protocol

**Message set.** One tagged union `MESSAGE`, checked by a compiled schema after
each decode unless the link is trusted (`src/link/message.ts:60-124`,
`:186-191`). It has 18 kinds, in binary kind-byte order
(`src/link/binary.ts:22-41`): `hello`, `hold`, `release`, `call`, `abort`,
`bound`, `state`, `failed`, `result`, `error`, `gone`, `retry`, `loading`,
`ack`, `closed`, `ping`, `pong`, `revoke`. The direction table is at
`docs/design.md:2072-2091`.

- `hello { protocol, incarnation (uuidv7), calls }` is sent first by both
  sides (`src/link/message.ts:62`). There is no name, no kind (host/client),
  no codeVersion and no acks flag.
- `hold { hold, type, version, fingerprint (16 hex), params (part), address
  {kind, params}, principal?, incarnation?, chain?, limit? }`
  (`src/link/message.ts:63-80`). It carries no contract description: only the
  version and fingerprint.
- `bound { holds: [{ hold, variant, members: [{member, value}], failed }] }` and
  `state { holds: [{ hold, members: [{member, ops}], failed, retired }] }`
  (`src/link/message.ts:89-100`). Member, method and variant are **indexes**
  into sorted names (`src/contracts/contract.ts:162-169`, `docs/design.md:2106-2107`).
- `failed { hold, cause {kind: transient|broken|waiting, error}, retryIn? }`,
  `loading`, `retry { hops 1..16 }` (`src/link/message.ts:84-87`, `:109-120`).
- Every kind except `hello`, `revoke`, `ping` and `pong` may carry `origin`
  (a relay's number for a downstream link) (`src/link/message.ts:13-18`, `:141-142`).
  On a child link, `origin` is a protocol error (`docs/decisions.md:2011-2016`).
- Errors use the wire form `{kind:"chord", error}` or
  `{kind:"plugin", code, message, details?}` (`src/link/message.ts:24-27`).

**Codecs.** Both ends use the same codec, chosen per link with no negotiation
(`src/link/README.md:46-68`).

- `binaryCodec` is the default. Each message starts with a kind byte, whose
  bit 0x80 means an origin varint follows. The fields are unsigned LEB128
  varints, length-prefixed UTF-8 strings, incarnations as 16 raw bytes and
  fingerprints as 8 raw bytes.
  - A part's prefix is its length × 2, plus 1 when the part is deflated.
  - Long texts use a padded 5-byte varint, which readers must accept.
  - There is no outer length.
  - Sources: `src/link/binary.ts:1-5`, `:63-196`, `:305-395`.
- `textCodec` writes positional JSON tuples (`["c", call, hold, method, args?]`
  and so on). It is meant for debugging, and `describeMessage` prints any
  message in this form (`src/link/README.md:58-68`).
- **Parts** (`params`, `args`, `value`, snapshot values, ops) are opaque JSON
  text or bytes. Only their owner parses them; relays forward them unparsed
  (`docs/design.md:2100-2105`).
- **Byte segments** carry `bytes()` leaves raw, referenced as `{"$bytes": i}`
  (`docs/design.md:2116-2118`).
- **Compression.** A part over 16 KiB may be raw-deflated by the sender. Child
  links refuse compressed parts, and compressed hold params are always a
  protocol error (`docs/design.md:2141-2154`, `src/link/README.md:103-112`).

**Handshake** (`src/link/channel.ts:220-235`). Each side queues its own
messages until the peer's `hello` arrives. The link closes with
`protocol_error` when the first message is no `hello` in this codec, when the
protocol number differs, or on a second `hello`. Nothing is negotiated; p2
reloads the page or TUI when the peer is newer
(`apps/p2/src/runtime/chord.ts:191`).

**What `PROTOCOL_VERSION = 1` versions.** It is defined next to the error table
(`src/data/errors.ts:6-7`, "Version of the error table below on links"). It is
also the single link protocol number that `Channel` sends in `hello` and
checks (`src/link/channel.ts:6`, `:86`, `:229`). Message kinds, error codes and
reasons, and the fingerprint normal form are all bound to it
(`src/data/README.md:59`, `src/contracts/fingerprint.ts:8-9`,
`docs/design.md:612`). It is unrelated to v1's protocol 4.

**Flow control.**

- **State window.** Per (link, origin), at most K = 2 unacknowledged
  `bound`/`state` messages. The consumer sends one `ack` per applied message.
  While the window is full, ops wait in per-member pending queues (folded, at
  most 10,000 ops, then replaced by a single `["r", value]`) and go out as one
  `state` message when a slot frees (`docs/design.md:368-383`).
- **Call window.** N = 256 calls per origin, announced in `hello`. Extra calls
  wait in a FIFO queue. More than N running calls is a protocol error. There
  is no per-link `maxCalls` (`docs/design.md:384-394`, `docs/slices.md:186-188`).
- **Heartbeat.** `ping` after 15 s of silence, close after 30 s, the handshake
  included (`docs/design.md:361-367`).
- **Relays** keep per-origin state, forward without renumbering ids, return
  acks through a senders FIFO, and send `closed {origin}` when a downstream
  link drops (`docs/design.md:399-445`).

**Transports:** `memoryLinkPair`; `ipcLink` over Node IPC with
`serialization: "advanced"` (Node-specific); `webSocketLink`, binary frames
only, where a **text frame closes the link** (`docs/design.md:334-350`,
`src/link/README.md:16-38`). There is no Unix-socket or NDJSON transport, so
noel's own transports stay noel's.

**Differences from protocol 4** (`crates/noel-chord/src/wire.rs:1-31`):

| v1 protocol 4 (noel today) | v2 |
| --- | --- |
| JSON text frames `{"t": ...}`; NDJSON `{"chord2": frame}` | binary codec (default) or text tuples; WebSocket text frames are fatal |
| `hello {protocol:4, name, kind, codeVersion, acks}` | `hello {protocol:1, incarnation, calls}` |
| hold carries a contract token (description); provider checks `coverage` | hold carries `version` plus `fingerprint` only; strict equality (or a provider `accepts` table) |
| placement `hostNamed`/`hostFamily`, host names like `session:<id>` | typed `address {kind, params}` from `hostAddress(params)` |
| `shape` then `state` with `as` snap/reset/ops/error | `bound` (snapshot, batched over holds), `state` (ops, batched, `retired`), `failed`/`loading`/`retry` |
| member names on the wire | indexes into sorted names |
| `sub`/`unsub`/`state:false`, `resync`, `again` | removed (C8, `docs/design.md:818-819`); a re-hold is a new `hold` |
| roots and `root_end` on relayed calls | no roots on the wire (`host.root` is local) |
| `invalidate`, `prepare`/`commit`/`abort`/`retire`/`vote`, `bye` | `revoke` only; reload is per host and never on the wire |
| link-wide pending budget, `maxCalls` | K = 2 per origin, N = 256 per origin |
| `cancel` | `abort` |
| origin on relayed holds only | origin on every message of relayed work, refused from children |

**Stability.** The wire is explicitly unstable. `PROTOCOL_VERSION` stays 1
until p3 ships (`docs/design.md:2066-2068`), and slices have changed messages
without a bump (`docs/slices.md:179-182`). "API names are working names"
(`docs/design.md:10`). Slice 9's trace carriers are still pending
(`docs/design.md:2155`). Recent commits keep touching link semantics, for
example `fc7d91f4e` (2026-11-03, "no per-link call limit").

## 2. Contracts and identity

- `remote(name, { version, params, hostAddress, variants })` and
  `local(name, { version, params, members })` (`src/contracts/README.md:7-30`,
  `docs/design.md:536-560`).
- **Names** use `[a-z0-9@/._~-]` (`docs/design.md:569-570`). Reserved member
  names are `then`, `release`, `state`, `retry` and `variant`
  (`docs/design.md:579-580`).
- **Params** are a flat, ordered record of required `str`, `int`, `bool` or
  `oneOf` fields. The identity key is the values in order, joined by `|`
  (`docs/design.md:593-597`). Params cannot change by evolution: changing them
  means a new history base (`src/contracts/README.md:63-64`).
- **Host kinds and addresses.** `hostKind("session", { id: str() })`, and
  `Session({id})` gives `{kind, params, key}`. `hostAddress` is required on
  remote contracts and is left out of the fingerprint. The caller computes the
  address, relays route by it, and the provider recomputes it, answering
  `invalid/host_address` on a mismatch (`docs/design.md:103-133`).
  `serverHost`/`sessionHost` are p2's names for `() => Server()` and
  `({session}) => Session({id: session})`
  (`apps/p2/docs/p2-notes.md:331-334`).
- **Variants.** A member has one kind across variants; a method has one
  signature across variants; state schemas may differ. The factory returns
  `{variant, members}`, and calls outside the variant fail `invalid/member`
  (`docs/design.md:587-592`).
- **Fingerprint.** `hash64(JSON.stringify({normalFormVersion: 2, value}))` over
  `{kind, params, variants}`: variants and members sorted; schemas normalized
  (keys sorted, annotations dropped, `required` and `enum` sorted, a keyword
  whitelist); the contract name and version are **not** in it; `hash64` is two
  FNV-1a lanes over **UTF-8 bytes** (`src/contracts/fingerprint.ts:8-69`,
  `src/contracts/snapshot.ts:29-53`, `:141-165`). The one golden is
  `test/contracts/fingerprint.test.ts:37` (`b3eda86070a7e319`). This is **not**
  noel's v1 `hash64` (UTF-16 code units, another second lane,
  `crates/noel-chord/src/schema.rs:62-71`); v1 fingerprints do not carry over.
- **Arguments.** Every object inside a method's arguments must be closed
  (`additionalProperties: false`), or declaration fails
  (`src/contracts/README.md:61-62`, `src/contracts/snapshot.ts:79-81`).
- **Errors.** The table of codes and reasons is closed, and a receiver rejects
  unknown reasons (`src/data/errors.ts:10-24`, `docs/design.md:611-620`).
  Application errors cross as `PluginError` (`{kind:"plugin", code, ...}`).

**noel's contracts** (`crates/noel-client/contracts/*.json`, `docs/spec.md:185-222`)
can be expressed as v2 contracts:

```text
Server  = hostKind("server")
Session = hostKind("session", { id: str() })
noel.sessions  params {}           hostAddress () => Server()    variants owner{directory; create, fork}
noel.chat      params {session}    hostAddress ({session}) => Session({id: session})
               variants participant{view; submit, withdraw, abort, compact, configure, resume}, viewer{view}
noel.models    params {}           hostAddress () => Server()    variants owner{catalog}
```

Changes needed:

- `input` becomes ordered `params`; absent args and results become
  `{type: "null"}`; no member name is reserved.
- Every args schema gets `additionalProperties: false` on each object, which
  changes the schemas and so the fingerprints. The keywords noel uses (`type`,
  `properties`, `required`, `items`, `enum`, `minLength`) are all in the
  whitelist (checked by script).
- noel's `invalid/busy`, `invalid/session`, `invalid/workspace`,
  `invalid/queued_prompt`, `invalid/request_id_reused` and `invalid/refused`
  (`docs/spec.md:216-219`) are **not** allowed reasons in v2. They must become
  plugin errors (for example code `busy`), which changes what clients match on.
  `not_in_variant` becomes `invalid/member`, and `upgrade_required` becomes
  `contract_mismatch`.
- The worker host address becomes `Session({id})` instead of the name
  `session:<id>`; `generation` stays in the worker principal.
- `coverage`/`fits` leave the wire: matching is strict fingerprint equality.
  Old clients can be served only through a provider-side `accepts` table plus
  `evolve` (`docs/design.md:2516-2551`), optional for noel.

Kernel APIs with no wire form (`createHost`, `load`, `route`, `root`; `docs/design.md:187-303`) still shape noel's Rust host API.

**Model.** The server is addressable, workers are addressable per kind, and
clients are not addressable and serve nothing remote (`docs/design.md:72-101`).
A worker `connect`s to the server as its parent and loads after that (W6);
after a drop it takes the next link and re-holds (`docs/design.md:283-290`).
This fits noel's workers that outlive their server: a new server's link becomes
the worker's next parent link, and the new incarnation in `hello` makes
consumers re-hold (`docs/design.md:315-325`).

## 4. Plugins

- **Protocol-level: nothing.** A plugin is a facet: the types it serves and
  its contributions to registries (`docs/design.md:1621-1650`). It is visible
  to peers only through the contracts it serves. Registries compose in
  process (`docs/design.md:1651-1744`).
- **Node-specific: all of the machinery.**
  - Discovery and builds with esbuild (`src/node/plugins/build.ts:1-20`,
    peer dependency `esbuild`, `package.json:146-148`).
  - Evaluation with `vm.Script.runInThisContext` (`src/node/plugins/evaluate.ts:1`, `:39`).
  - The versioned app API import checks, installs from git and npm, and
    `testPlugin` (`CHANGELOG.md:12`, `docs/plugin-authoring.md`).
  - Shipping built scripts to workers in the start message
    (`docs/design.md:2276-2302`).
  - Web and TUI plugin scripts as self-registering bundles (`CHANGELOG.md:14`).
- **Visible to the protocol only through reload:** a provider unbinding
  holds (`failed {waiting}`, `not_served` or `version`), restarts (`loading`,
  then a fresh `bound`) and swaps (a fresh `bound`, possibly another variant)
  (`docs/design.md:2168-2175`).
- **For noel:** it needs none of this. It must only accept a re-`bound` on a
  bound hold and `failed` on a bound hold when it is a client of an upstream
  host. noel's register already lists "no reload, plugins or code versions"
  (`docs/rust-rewrite/non-parity-register.md`, "Chord Link and Hosts").

## Port plan

**What stays noel's own** (none of it is Chord wire): `noel bridge` and the
ssh tunnel (bytes only); `noel worker` as a separate process that outlives the
server, with adoption by build id; the JSONL journal and session store; device
access over the Unix socket by peer uid, with `Noel-Via` stamping; the runtime
directory layout; the server/worker control messages (`ready`, `status`,
`shutdown`).

**Pin.** Use `3551ec07eb87afebac20191958163ae58976f1d0` (2026-11-03, the
newest commit touching `packages/chord`, `packages/schema` or
`packages/telemetry`; `7dc38ff` adds nothing to them). Keep the
`CHORD_REFERENCE_REF` mechanism and `ts-parity-drift` (`Makefile:15`), with a
separate variable such as `CHORD2_REFERENCE_REF` while v1 still runs.

**Steps, in order:**

1. **Reference image.** Extend `Dockerfile.ts-parity` (`:45-61`) to check out
   the v2 pin. v2 needs `@earendil-works/pi-schema` and `pi-telemetry`, plus
   `ws` for interop. esbuild and react are optional peers, not needed
   (`package.json:142-158`). Whether `npm --prefix packages/chord run build`
   succeeds at the pin is **unverified**.
2. **Contracts (L1) in Rust.** New `noel-chord` modules: the schema snapshot
   and normal form (keyword whitelist, closed-args check, sorting); `hash64`
   v2 (UTF-8, two FNV-1a lanes); the fingerprint over `{kind, params,
   variants}`; params identity keys and host kinds/addresses; variant and
   member index order; the v2 ChordError table with `PluginError`. Golden
   fixture: a TS script declaring noel's three contracts and some edge cases,
   printing fingerprints and normal forms, which Rust must match byte for
   byte. This is the cheapest high-value check; do it first.
3. **Messages and codecs.** A `Message` enum checked like `MESSAGE`; the
   binary codec (padded varints, part prefix ×2+1, 16- and 8-byte raw fields,
   segments); the text codec. Golden fixture: a TS script that encodes a table
   of messages with `binaryCodec`/`textCodec` and writes hex plus tuples, as
   `chord-link.json` does today. Both directions are checked: noel decodes TS
   bytes, and TS decodes noel bytes.
4. **Channel.** `hello` with uuidv7 incarnations, queueing until the peer's
   `hello`, protocol errors, the heartbeat (15 s / 30 s), part limits
   (16 MiB wire / 64 MiB decoded on untrusted links), and inflate of deflated
   parts from parents and routes (flate2, raw deflate). noel need never
   compress what it sends.
5. **Provider and consumer sides.** Holds by (origin, id); `bound` and `state`
   batching (one `state` per commit per link and origin); K = 2 and pending
   queues with folding; call window N = 256 with a FIFO queue; `failed`,
   `loading`, `retry` (hops), `gone`, `retired`; principals on holds honoured
   only from the parent; `revoke`. Port behaviour from
   `src/remote/{provider,consumer,hold,calls,replica}.ts` (about 2.7k lines of
   TypeScript for all of `src/remote`).
6. **Relay.** Server-side relay from client links to worker route links:
   per-origin numbering, `closed`, the ack senders FIFO, upstream-drop
   `loading`, and unparsed parts (`src/remote/relay.ts`, `docs/design.md:399-445`).
7. **Transports.** WebSocket binary frames on the device socket and the
   bridge (only the frame type changes). Server to worker: replace NDJSON
   `{"chord2": ...}` with length-prefixed binary frames plus a tagged control
   frame, or WebSocket binary frames; the link is noel-internal and trusted,
   so it is not interop-critical.
8. **noel-cli and noel-client.** Re-declare the three contracts (section 2),
   map `session:<id>` to `Session({id})`, turn noel's app reasons into plugin
   error codes, update `noel-client`'s `Connector`/`Client` and the attached
   TUI's error matching, and update `docs/spec.md` sections 6-7 and the
   non-parity register.
9. **Interop.** Add `make chord2-interop`, modelled on
   `scripts/chord-interop.sh` (Docker image, a shared socket directory, the
   caller's uid, `ws+unix://.../chord`). Scenarios:
   - (a) An upstream client host (`createHost`, `load([])`, `connect`,
     `hold(NoelChat, {session})`) against `noel server`: snapshot, then ops
     after `noel client send`. A fingerprint mismatch would show as
     `failed {waiting}` `contract_mismatch`.
   - (b) A noel client against an upstream server host serving a test
     contract.
   - (c) A drop and re-hold.
   - (d) A relay through `noel server` to a worker.
   - (e) A slow consumer (window), adapted from `test/examples/14-flow-control.ts`.

   Run the TS side with Bun if possible (CLAUDE.md prefers Bun; today's
   scripts run `npx tsx` in Docker, `Makefile:207-211`). Whether Bun runs
   upstream's `ws` WebSocket over a Unix socket is **unverified**.
10. **Cut-over.** v1 and v2 cannot share a link: a v2 peer refuses text frames
    and a protocol-4 `hello`. Switch noel server, workers and clients in one
    release; old workers get `shutdown` through the existing build-id
    adoption check. Then delete v1 frames, `coverage`/`fits`, NDJSON and
    reload stubs, and retire `chord-link.json` and `make chord-interop`.

**Rough size (Rust lines):** contracts 1.0-1.5k; messages and codecs
1.2-1.5k; channel 0.5k; remote and relay 3-4k, replacing most of `host.rs`
(4.2k); noel-cli and noel-client 1-1.5k; fixtures and tests 2k. That is 8-11k
lines changed in all, about 6-7k of it new protocol code.
Upstream's `src/link` + `src/remote` + `src/contracts` + `src/data` total about
7.1k lines of TypeScript.

**Risks:**

- **Wire churn before p3 ships.** Changes come without a version bump, so a
  pinned peer and a newer peer fail at `hello` or only later. Mitigation: pin,
  run `ts-parity-drift`, and re-run interop on every pin move.
- **Fingerprint drift.** Any schema edit (closing args) changes fingerprints,
  and a byte difference in the normal form (key order, serde_json vs.
  `JSON.stringify` number formatting; see the register's float note) leaves
  holds `failed {waiting}` silently. Mitigation: fingerprint goldens first.
- **Error reasons.** noel clients currently match `invalid/<reason>` and must
  move to plugin codes.
- **Semantics with no fixture.** The dependency-model states (`waiting`,
  `retryIn`, the publication gate) and K = 2 pending folds need behavioural
  tests, not just frames.
- **Compression.** Inflate is required whenever noel is a client of a
  compressing upstream host.
